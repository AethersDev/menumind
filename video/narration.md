That film was scripted, but every ticket, rule and price in it came from MenuMind's code. Here is the real app, on a live model.

## S02 · 2:41.9–3:03.6 · The brief, and my challenge

The brief: recommend from a real menu, remember each customer, and adapt when they change their mind. For my challenge I chose memory over voice, scale or integrations, because in food, memory mistakes are the costly ones: an allergy forgotten, a one-night wish kept forever, an allergy dropped on a misread sentence.

## S12 · 4:29.4–4:47.1 · How it works

The design in one line: the model describes, code decides. The model turns messages into claims and writes the reply. Code decides what is saved, keeps every change in an event log, filters the menu, and lets the model pick only verified dishes.

## S13 · 4:47.1–5:07.7 · One conflict, end to end

The hard case: Maya says she's no longer allergic. The model reads it, but can't write memory. Rule R10 asks first, so peanut stays enforced. The question is bound to this conversation and her log, so a stale yes is refused. Her yes appends one confirmed event; nothing is overwritten.

## S14 · 5:07.7–5:24.3 · Grounded replies

Replies are grounded the same way: the model returns dish IDs, code checks them against her restrictions and writes names and prices from the menu. Twice wrong, and the app answers from verified data; unreadable, and nothing is saved.

## S15 · 5:24.3–5:36.6 · Menu data

And the menu only loads if every dish's allergens match its ingredients, recipes inside recipes included. Cross-contact isn't covered, and the app says so.

## S16 · 5:36.6–5:58.4 · Scope and trade-offs

What I left out was deliberate: learning preferences from behaviour, a clock for 'tonight', and running on several servers. I rejected letting the model write memory directly, because nothing it saved could be audited. With more time: one transaction per message, concurrency control for more servers, and verified supplier recipes.

## S17 · 5:58.4–6:21.2 · Tests and evidence

Validation: a hundred and ninety-six tests without a model, with faults injected to prove they catch regressions, and an acceptance test over HTTP across a restart. On the real model, all forty-two scripted conversations passed, with no unsafe recommendation in seventy-five turns. A limited set: counts, not rates.

## S18 · 6:21.2–6:32.9 · What the live runs caught

The live runs earned their cost: they caught 'nuts' saved as tree nuts only, and a rule of mine that dropped a companion's allergy. Each was fixed, and re-run.

The guarantee is narrow, and strong: the model can describe; code decides. Thank you for watching.
